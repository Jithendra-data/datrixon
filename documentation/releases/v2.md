# Datrixon 2.0.0 — Governed ERP Intelligence

## Evolution from V1

V1 established deterministic synthetic ERP generation, normalized staging, SQLite dimensions/facts, SQL/Python analytics, independent reconciliation and safe publication. V2 places executable metric governance, source contracts, lineage, trust and a bounded analytical assistant around that same pipeline.

## Implemented changes

- 19 metric definitions; 16 certified executable measures, three intentionally blocked draft definitions.
- 14 versioned source contracts and breaking schema-drift checks.
- Read-only SQL semantic API, source/warehouse/dashboard equivalence, governed yearly measures.
- Additional OrderService reference table for booking/service grain without changing existing invoice facts.
- Column lineage, SQL dependency validation and downstream impact traversal.
- Ten explicit trust dimensions and deterministic Ready / Conditional / Blocked assessment.
- Role-policy evaluation, Restricted classification denial and fail-closed local analytical operations.
- Answer provenance, citations, local build audit, session events, data version identity and warehouse hashes.
- Eleven governance views alongside retained V1 analytics and routes.
- Negative metadata, policy, source drift, semantic, publication, assistant and browser tests; CI governance and credential-pattern validation.

Publication contract version is 5. Governance release version is 2.0.0; initial source contracts and metric definitions are 1.0.0. Numeric labels are separate identities, not interchangeable version numbers.

## Release verification

See [verification](../../testing/v2_verification.md) for commands and recorded results. CI gates both Pages deployment and scheduled refresh. Failed candidates never replace approved public JSON. The public release includes measured pipeline metadata, not fabricated performance claims.

## Simulated and future boundaries

Demo roles are not authentication. Incident UI overrides copied decisions; actual data corruption is tested in isolated builds. Named owners are demonstration responsibilities, not a real governance council. The assistant is deterministic and cannot reason outside its supported questions. There is no live ERP, LLM service, corporate SSO, RLS, multi-tenant security, durable browser audit, production SLA or measured business ROI.

SQLite remains a full-rebuild reference warehouse with REAL amounts and explicit tolerances. Source/dataset catalogs are metadata for this project, not discovery across enterprise systems. Detail responses disclose their extract caps. Historical business time stays separate from batch freshness. These choices keep the demonstration reproducible and compatible with GitHub Pages.

## Run locally

```bash
python -m pip install -r requirements.txt
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
python -m etl.run_pipeline
python -m unittest discover -s tests -p 'test_*.py' -v
python -m tests.smoke_pipeline
python -m governance.validate --source data/raw
python -m validation.publication
python -m tests.security_scan
pnpm test
pnpm test:browser
python -m http.server 8000 --directory web
```

Use a Python virtual environment and a supported Node version. `--workspace .test-run/example --orders 1000 --purchase-orders 250` builds a small isolated scenario. `--skip-generation` replays existing source files. Browser tests support `NORTHSTAR_BROWSER_CHANNEL=msedge` when using an installed Edge browser locally; CI uses Playwright Chromium.
